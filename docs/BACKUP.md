# النسخ الاحتياطي

يوجد خياران للتصدير من «المزيد ← نسخ احتياطي»:

1. **نسخة عادية** — `daftari-backup-<timestamp>.db`
   نسخة خام ثنائية من ملف قاعدة بيانات SQLite (بعد `PRAGMA wal_checkpoint(FULL)`).
   تنفذها الدالة `BackupManager.exportDatabase()`؛ لا يوجد مسار JSON في الكود.
2. **نسخة مشفّرة** — `daftari-backup-<timestamp>.enc`
   نفس الملف لكنه مشفّر بـ AES/GCM مع اشتقاق المفتاح من كلمة المرور عبر PBKDF2
   (راجع `EncryptedBackup.kt`).

> ملاحظة: لا تُصدَّر بيانات بصيغة JSON في هذا الإصدار؛ النسخة حرفية من قاعدة
> البيانات، وهي أسرع وأكثر موثوقية من تجميع/تحليل JSON لكل الجداول.

## النسخ الاحتياطي الرسمي عبر Google

- يستخدم Credential Manager للمصادقة وAuthorizationClient لتفويض النطاق المحدود `drive.appdata`.
- تُحفظ النسخ كملفات `.dfb` كاملة ومستقلة داخل `appDataFolder` المخفي في Google Drive.
- تحتوي الحزمة على manifest وإصدار القاعدة وبيانات الجهاز وchecksums وقاعدة SQLite المضغوطة.
- لا تُخزن كلمات مرور Google أو Access/Refresh tokens.
- تعرض شاشة مستقلة الحساب والحالة وآخر نجاح والحجم والشبكة والنسخ المتاحة والاستعادة.
- راجع `docs/GOOGLE_BACKUP_SETUP.md` لإعداد OAuth وDrive API واختبار جهاز جديد.

## النسخ السحابي الاختياري القديم
- يمكن ربط مجلد من منتقي ملفات Android؛ عند وجود تطبيق Google Drive يمكن
  اختياره مباشرة من المنتقي دون مفاتيح OAuth داخل التطبيق.
- يمكن إعداد مجلد WebDAV (Nextcloud وغيره). تُحفظ بيانات الدخول في
  `EncryptedSharedPreferences` ولا تُكتب في قاعدة البيانات أو السجل.
- النسخ التلقائي يرفع النسخة المحلية إلى كل وجهة سحابية مفعلة، مع بقاء
  التطبيق صالحًا للعمل دون شبكة.
- تدعم الواجهة استعادة ملف من مزود الملفات أو أحدث نسخة WebDAV، ثم تعيد
  تشغيل العملية تلقائيًا على قاعدة البيانات المستعادة.

## الاستعادة
1. التحقق من الحجم وترويسة SQLite (`SQLite format 3`) قبل لمس قاعدة البيانات
   الحالية.
2. للنسخة المشفّرة: فك التشفير في ملف مؤقت والتحقق منه أولاً. كلمة المرور
   الخاطئة أو الملف التالف لا يغيران البيانات الحالية.
3. إنشاء **نسخة أمان** من القاعدة الحالية باسم `pre-restore-<timestamp>.db`
   بعد نجاح التحقق فقط (ولا تُحذف تلقائيًا مع دورة النسخ الآلية).
4. إغلاق قاعدة البيانات، حذف ملفات `-wal`/`-shm` القديمة، ثم استبدال الملف.
5. إسقاط الـ singleton في `AppDb` وإعادة بنائه (`AppDb.invalidate`).
6. إعادة تشغيل العملية/الواجهة تلقائيًا (`MainActivity.restartApp`) حتى لا
   يبقى `Repository` قديم يحمل مرجعًا مغلقًا.

## النسخ الاحتياطي التلقائي
- مجدول عبر `WorkManager` كل 24 ساعة (`AutoBackupWorker`).
- يحتفظ بـ `autoBackupKeep` (افتراضي 7) نسخ آلية (الملفات `.db` ذات البادئة
  `daftari-backup-`).
- عند الدوران **لا يُحذف** سوى فائض النسخ الآلية؛ تُترك النسخ المشفّرة اليدوية
  ونسخ الأمان `pre-restore-*` كما هي.
